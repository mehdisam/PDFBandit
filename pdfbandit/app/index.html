    Preferences

    On-device translation: checking…

    Translation uses Chrome's built-in on-device model (chrome-ai — private, no key, but Chrome-only), a public LibreTranslate instance (default lt.dialectapp.org) or a custom URL; the public instances are community servers, so expect rate limits or the occasional outage. The manual copy-and-paste workflow always works.

    Both language fields also pre-select the region toolbar. Auto source lets the provider detect the language (Chrome's on-device model needs a named one). Choosing a LibreTranslate server fills the URL field with that server's address — edit it freely to point anywhere; pick LibreTranslate (custom URL…) for a server that is not listed.

    There is no Translate-or-Improve question on import: a new PDF opens straight into this workflow and you switch anytime with the header buttons. Both workflows share the same map and content variants — switching never writes or rewrites anything.

    OCR runs entirely in this browser (Tesseract.js, Apache-2.0); the engine and language data download from jsDelivr on the first scanned extraction and are then cached. The OCR language follows the PDF/source language; Auto falls back to English. Table recognition remains out of MVP.

    OCR is used by Improve ▸ Make this selectable, the region context menu’s Read with OCR, translation from page text, and Detect-and-extract. Detection alone never starts the OCR engine; scanned regions stay badged not selectable yet until a harvest runs.

    Text box padding grows a detected region by that many points per side, so the polygon (and its mask) gains a margin and a text box — the region interior inset by the same amount — keeps the room the detector gave the text (0 = flush). It is applied when regions are detected, never when a text box is added; a region you drew yourself keeps exactly the shape you drew and its box is simply inset by the padding. Re-detection overlap threshold is the IoU at which a re-run treats a proposal as the same block: above it the conflict is reviewed (Replace / Don't add); containment always counts; match-and-identical proposals are left alone, so re-detecting an unchanged page changes nothing. Scanned-page detection picks the detector per page: Auto uses the text layer when the page has one and the CV detector when it does not; force either to override, per run. CV engine picks how the CV detector segments the bitmap: classical is dependency-free and instant; OpenCV.js is experimental and downloads ≈10 MB on first use (browser-cached, never at startup) to use OpenCV's adaptive threshold and morphology; it then falls back to classical with a status note if it cannot load. Both engines share the same structural text/image classifier, type-aware grouping and proposal contract; OpenCV currently matches, rather than beats, classical on the reference cover.

    About PDFBandit

    Fix/Translate PDFs, your way.

    Version 1.0.0 · spec revision 1.6

    PDFBandit fixes and translates PDFs your way: map a page once, then write or translate text into language variants and export a reconstructed or selectable PDF. The source PDF is never modified.

    Projects use a shared .pmap map plus per-language .content.json variants. Your PDF, map and variants stay in this browser (IndexedDB); translation text goes only to the provider you choose, and OCR runs on-device.

    Find & replace

    Enter starts a new line, Tab moves between table cells. Done (or Esc) keeps the text, Cancel discards it. This dialog only writes, edits and formats — size the box on the page (its handles, or Resize to text / R).
