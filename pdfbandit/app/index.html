    Preferences

    Default font, font size and line spacing are used for new text items and as the base style when the text editor opens. Existing text keeps its own formatting; bold, italic and underline always start off (regular) so new typing never inherits bold from a previous item.

    On-device translation: checking…

    Translation uses Chrome's built-in on-device model (chrome-ai — private, no key, but Chrome-only), a public LibreTranslate instance (default lt.dialectapp.org) or a custom URL; the public instances are community servers, so expect rate limits or the occasional outage. The manual copy-and-paste workflow always works.

    Both language fields also pre-select the region toolbar. Auto source lets the provider detect the language (Chrome's on-device model needs a named one). Choosing a LibreTranslate server fills the URL field with that server's address — edit it freely to point anywhere; pick LibreTranslate (custom URL…) for a server that is not listed.

    OCR runs entirely in this browser (Tesseract.js, Apache-2.0); the engine and language data download from jsDelivr on the first scanned extraction and are then cached. The OCR language follows the PDF/source language; Auto falls back to English. Table recognition remains out of MVP.

    OCR is used by Content ▸ Make Selectable, the region context menu's Read with OCR, translation from page text, and Detect-and-extract. Detection alone never starts the OCR engine; scanned regions stay badged not selectable yet until a harvest runs.

    Text box padding grows a detected region by that many points per side, so the polygon (and its mask) gains a margin and a text box — the region interior inset by the same amount — keeps the room the detector gave the text (0 = flush). It is applied when regions are detected, never when a text box is added; a region you drew yourself keeps exactly the shape you drew and its box is simply inset by the padding. Re-detection overlap threshold is the IoU at which a re-run treats a proposal as the same block: above it the conflict is reviewed (Replace / Don't add); containment always counts; match-and-identical proposals are left alone, so re-detecting an unchanged page changes nothing. Scanned-page detection picks the detector per page: Auto uses the text layer when the page has one and the CV detector when it does not; force either to override, per run. CV engine picks how the CV detector segments the bitmap: classical is dependency-free and instant; OpenCV.js is experimental and downloads ≈10 MB on first use (browser-cached, never at startup) to use OpenCV's adaptive threshold and morphology; it then falls back to classical with a status note if it cannot load. Both engines share the same structural text/image classifier, type-aware grouping and proposal contract; OpenCV currently matches, rather than beats, classical on the reference cover.

    Ctrl/Cmd+OOpen PDF (it loads straight in — a region map and a content variant are created or loaded on demand when you first need them: Detect/Add polygon, Translate/Make Selectable, Add text, Add image)
    Ctrl/Cmd+SExport the project: writes the shared .pmap region map and, when a content variant is loaded, its .content.json as files from this browser. The Export button in the app bar does the same; its ▾ menu writes one half at a time.     Ctrl/Cmd+FFind & replace in the content the current workflow is editing: the active Translate content variant, or the Improve Selectable text variant. It searches every page of the loaded content, respects paragraph, list-item and table-cell boundaries, keeps character formatting, and supports a Regular expression mode and Match case. Replace all is one undo step; a zero-width regex match is ignored
    Region map & content on diskA project is two separate files: a structure-only .pmap region map (pages, region ids, polygons, locks) and one .content.json content variant per language/direction (backgrounds + content items, keyed by region id). The same map can back many variants; only one variant is active at a time. File ▸ New region file… creates a fresh map for the open PDF; File ▸ Open region file… loads one; File ▸ New content variant… adds a variant (empty, or a copy flagged for review); File ▸ Open content… loads one. A region map must exist before a content variant can be loaded, and unloading a region map unloads its content too. A v1.1 single-file map must be split first with tools/pmap-migrate.mjs
    Browser refreshThe open PDF, its map and the active content variant are remembered in this browser (IndexedDB) and restored on reload — nothing is uploaded. Closing the PDF (or opening another) clears that saved session, and the empty state after a close starts fresh
    Close PDFThe app bar's × (or File ▸ Close PDF) closes the document. When any file has not been exported in this session, one combined dialog lists every pending file — the .pmap, the active .content.json, or both — with Export, Close without exporting or Cancel. Browser autosave is separate: closing always clears this PDF's saved session and its per-document language choice, then returns to the empty editor. Other preferences are kept
    WorkflowsTranslate and Improve are intents, not data states: one PDF, one map, one set of variants. A new PDF opens straight into Improve when its variant's source equals its destination, or Translate when they differ; File ▸ New content variant… lets you pick. Translate works in the target-language variant and returns there; Improve foregrounds the PDF-language variant, labelled Selectable text. The text you type in Improve is the same source text Translate reads.
    Export digitalized PDF…Writes a copy named <stem>.digitalized.pdf with an invisible, selectable text layer over every region that holds text in the PDF-language variant. The source PDF is untouched and the page looks unchanged. Regions with no extracted text (including not selectable yet and figures) stay uncovered; the status bar reports how many. If the PDF-language variant is not loaded, the command first runs the normal extraction flow.
    File ¸ Export PDF\u2026Writes a reconstructed PDF (.recon.pdf) with your region edits and content applied. Unlike digitalized export, this does not add a selectable text layer — it renders the page with your background colors, text items, and image items. The source PDF is untouched.
    Status tags (Shift+D)Toggles the on-page status tags (Shift+D). Text regions show their detector class (heading / text; a hand-drawn region reads text), plus has source text / selectable when the PDF-language variant already has content, or source text not readable / not selectable yet when it has none and OCR could not fill it. Detected figures stay untagged and keep their dashed outline. Shift+D hides only these tags, so ids stay visible; Shift+I hides the ids together with them and still leaves every outline in place. The tags are an inspection aid and never change the map or content.
    Select not selectablesContent ▸ Select not selectables (Shift+A) selects every text-convertible region on the current page that has no content in the PDF-language variant. Detected figures and filled regions are left out; regions whose source text is unreadable are included.
    Make SelectableReads the PDF into the Selectable text variant: the text layer, or OCR for scanned and mixed-page regions with no usable selectable text when Preferences… ▸ OCR Service is on. Choose selected region(s), this page, or all pages. Regions that already hold content are skipped; detected figures are not OCR candidates. One undo step per run, and the source PDF is never modified.
    Read with OCR (right-click)On a region badged source text not readable / not selectable yet, right-click it in Region mode and choose Read with OCR: Tesseract reads only the right-clicked region, never the whole page or the rest of a multi-selection, and writes the result into the PDF-language variant as review-flagged text. OCR runs on-device and leaves the region waiting if it cannot read it.

Its header holds the text tools: Bold / Italic / Underline / color / font / size / line / align / direction, plus H (heading) / • / 1. (lists) / ▦ (table). Formatting applies to the selected text only; with no selection it becomes the style of the next characters you type. Alignment applies to the current paragraph or cell. Line sets the line spacing of the whole box (a multiple of the font size, default 1.25): it is saved with the item, the box grows so no line is cropped, and table rows keep their own height. Inside a table cell, Tab/Shift+Tab move between cells, the column/row handles can be dragged to resize, and the table tool group appears (border color/width, add/remove row/column, column width, row height).     The app bar holds the document, the two workspaces and the View menu. Content is the default workspace once a map exists: click a box to select it, T adds text, Ctrl/Cmd+V pastes an image, and a box can be dragged, resized or double-clicked to edit. Edit regions is the geometry editor: press P (or Tools ▸ Add polygon) then click points to draw a polygon, or click a region to grab & move it; vertices and edges are interactive only there. Preview and Original live in View and return on Esc. Original shows the PDF's own text layer so you can select it. Workflow: open a PDF (it loads straight in) → create or load a region map (the map/file controls in the inspector or File menu) → create or load a content variant → map regions in Edit regions → fill in content in Content → export (document.pmap + document.en.content.json). The content variant's source/destination language determines the workflow: equal = Improve (make selectable), different = Translate. A deselected region that already holds content is rendered just as Preview and the export render it — its patch background plus its content items; the region you are editing stays transparent so you always see the page you are working on. Source PDF is never modified. Translation uses a public LibreTranslate instance (default lt.dialectapp.org, change it — URL included — in Preferences…); pick None (manual / external) there to copy the underlying content as an image, translate externally, and paste it back.

    About PDFBandit

    Fix/Translate PDFs, your way.

    Version 3.0.0 · spec revision 3.0

    PDFBandit fixes and translates PDFs your way: map a page once, then write or translate text into language variants and export a reconstructed or selectable PDF. The source PDF is never modified.

    Projects use a shared .pmap map plus per-language .content.json variants. Your PDF, map and variants stay in this browser (IndexedDB); translation text goes only to the provider you choose, and OCR runs on-device.
